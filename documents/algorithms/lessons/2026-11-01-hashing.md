# Hashing

**Məqsəd:** Hashing şablonunu nə vaxt seçəcəyini tanımaq, `Map`/`Set` ilə O(N) həll yazmaq, Two Sum, Group Anagrams və Longest Consecutive Sequence məsələlərini həll etmək.
**Ön şərtlər:** Big-O (O(N), O(N²)), array/string əsasları.

## Nə vaxt istifadə olunur

Məsələdə bu suallardan biri varsa, Hashing işə yarayır:

- "Bunu əvvəl görmüşəmmi?"
- "Neçə dəfə görmüşəm?"
- "Bu element hansı qrupa aiddir?"

## Mental model

Hash table bir "yaddaş dəftəri"dir. Massivi bir dəfə gəzirsən. Hər addımda dəftərə baxırsan (orta hesabla O(1)), sonra lazım olanı ora yazırsan. Beləliklə iç-içə iki dövrə (O(N²)) bir keçidə (O(N)) çevrilir. Bunun qarşılığında əlavə O(N) yaddaş xərclənir.

- `Set`: yalnız "var/yox" lazım olanda.
- `Map`: dəyər saxlamaq lazım olanda (index, sayğac, qrup).

## Nümunə: Two Sum

```ts
function twoSum(nums: number[], target: number): [number, number] | [] {
  const seen = new Map<number, number>(); // value -> index
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need)!, i]; // əvvəl görmüşəm
    seen.set(nums[i], i); // indi yadda saxla
  }
  return [];
}
```

Brute force bütün cütləri yoxlayır və O(N²) işləyir. Burada hər element üçün "tamamlayıcısı (`need`) artıq görülübmü?" sualı verilir, nəticədə O(N) olur. Əvvəl yoxlayıb sonra yazmaq vacibdir: belə element özü ilə cüt düzəltmir.

## Group Anagrams: düzgün key seçimi

Anagramlar eyni qrupa düşməli olduğu üçün hər anagram üçün eyni key alınmalıdır. İki variant var:

- **Sıralanmış string:** `"eat"` → `"aet"`. Bir sözün key-i O(K log K) çəkir.
- **Hərf sayğacı:** 26 hərfin sayı, məsələn `"1#0#0#…"`. Bir sözün key-i O(K) çəkir. Müsahibədə bunu follow-up optimizasiya kimi göstərmək yaxşıdır.

```ts
const groups = new Map<string, string[]>();
for (const s of strs) {
  const key = [...s].sort().join(""); // string key — vacib
  (groups.get(key) ?? groups.set(key, []).get(key)!).push(s);
}
return [...groups.values()];
```

## Longest Consecutive Sequence: niyə O(N)

Bütün ədədləri `Set`-ə yazırsan. Sayma yalnız ardıcıllığın **başlanğıcından** başlayır, yəni `!set.has(n - 1)` olan ədəddən. Beləliklə hər ədədə ən çox 2 dəfə baxılır və cəmi O(N) olur. Bu şərt olmasa ən pis halda O(N²) alınır.

## Edge case-lər

- **Dublikatlar.** Two Sum-da `[3,3]` və `target=6` halını əvvəl yoxlayıb sonra yazmaq sırası düzgün həll edir.
- **Mənfi ədədlər, boş massiv, tək element.**
- **Massiv və ya obyekt key kimi.** JS `Map` obyekt key-ləri **reference** ilə müqayisə edir: `[a,e,t] !== [a,e,t]`. Ona görə key-i string-ə çevirmək lazımdır.
- **Map-in xüsusi müqayisəsi.** `Map` SameValueZero istifadə edir, ona görə `NaN` key-i işləyir.
- **Object-i hash kimi işlətmək.** Bu halda `"__proto__"` və `"constructor"` kimi prototype key-ləri ilə toqquşma riski var. `Map` istifadə et.

## Trade-off-lar

- **Vaxt və yaddaş.** Vaxt O(N²)-dən O(N)-ə düşür, amma yaddaş O(1)-dən O(N)-ə qalxır.
- **"O(1)" orta haldır.** Collision olanda ən pis hal O(N) olur. Bunu müsahibədə bir cümlə ilə qeyd etmək kifayətdir.
- **Input sorted-dirsə və ya yaddaş məhduddursa.** Two Pointers ilə O(1) yaddaş kifayət edir.
- **Key aralığı kiçikdirsə** (məsələn, 26 hərf). `Map` əvəzinə `int[26]` massivi daha sürətli və sadədir.

## Big tech müsahibə axını

1. Əvvəl brute force-u və onun mürəkkəbliyini de, məsələn O(N²).
2. "Bunu əvvəl görmüşəmmi?" sualını tanı və Hash ilə O(N)-ə endir.
3. Yaddaş trade-off-unu özün qeyd et.
4. Gözlənilən follow-up-lar:
   - "Yaddaş məhduddursa?" → sort + two pointers.
   - "Data stream gəlirsə?" → hash map yenə işləyir.
   - "LRU Cache dizayn et" → `Map` + insertion order, ya da hash + doubly linked list.

## Ümumi səhvlər

- Two Sum-da əvvəl yazıb sonra yoxlamaq. Nəticədə element özü ilə cüt düzəldir.
- Array və ya obyekti key kimi istifadə etmək.
- `map[key] = v` yazmaq (`set` əvəzinə). Bu halda `has` və `size` həmin dəyəri görmür.
- Longest Consecutive-də başlanğıc yoxlamasını unutmaq.

## Məşq siyahısı

- **Əsas:** Two Sum, Ransom Note.
- **Sonra:** Group Anagrams, Longest Consecutive Sequence, Insert Delete GetRandom O(1), LRU Cache, First Missing Positive.

## Quiz

> Əvvəl özün cəhd et, sonra cavablara bax.

**Tapşırıq (kod yaz).** *Contains Duplicate II.* `nums` massivi və `k` verilir. Elə `i ≠ j` varsa ki, `nums[i] === nums[j]` və `|i − j| ≤ k`, `true` qaytar. Həll O(N) olsun.

**1. Konseptual.** Two Sum-da input artıq **sorted**-dir və müsahibəçi "O(1) əlavə yaddaş" tələb edir. Hash niyə ideal deyil və nə istifadə edərdin?

**2. Kod oxuma.** Bu kod `[100, 4, 200, 1, 3, 2]` üçün nə qaytarır? `while` dövrünün gövdəsi cəmi neçə dəfə işləyir?

```ts
const set = new Set(nums); let best = 0;
for (const n of set) {
  if (!set.has(n - 1)) {
    let len = 1;
    while (set.has(n + len)) len++;
    best = Math.max(best, len);
  }
}
```

**3. Debugging.** Bu Group Anagrams kodu hər sözü ayrı qrupa qoyur. Niyə? Necə düzəldərsən?

```ts
const m = new Map<string[], string[]>();
for (const s of strs) {
  const key = [...s].sort();
  if (!m.has(key)) m.set(key, []);
  m.get(key)!.push(s);
}
```

<details>
<summary>Tapşırıq: Contains Duplicate II</summary>

```ts
function containsNearbyDuplicate(nums: number[], k: number): boolean {
  const last = new Map<number, number>(); // value -> son görüldüyü index
  for (let i = 0; i < nums.length; i++) {
    const j = last.get(nums[i]);
    if (j !== undefined && i - j <= k) return true;
    last.set(nums[i], i); // həmişə ən son index-i saxla
  }
  return false;
}
```

- **Mürəkkəblik:** vaxt O(N), yaddaş O(N).
- **Niyə son index:** ən son index ən yaxın məsafəni verir.
- **Alternativ (sliding window):** ölçüsü `k` olan `Set` saxla. `i > k` olanda `nums[i-k-1]`-i sil. Bu halda yaddaş O(min(N, k)) olur.

</details>

<details>
<summary>1. Konseptual</summary>

Hash O(N) əlavə yaddaş tələb edir, ona görə tələbi pozur. Input sorted olduğu üçün **Two Pointers** istifadə et:

- `L = 0`, `R = n - 1`.
- Cəm `< target` → `L++`.
- Cəm `> target` → `R--`.

Nəticə: vaxt O(N), yaddaş O(1). Bu, LeetCode 167 *Two Sum II* məsələsidir.

</details>
