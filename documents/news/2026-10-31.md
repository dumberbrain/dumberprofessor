### 1. Backdoor in Claude Code for VS Code extension on the Cursor Marketplace

*Təhlükəsizlik xəbərdarlığı* · security, ai-llm · Claude Code, Cursor, VS Code extensions, SSH

Phorion təhlükəsizlik şirkəti Cursor Marketplace-dəki "Claude Code for VS Code" extension-ının 2.1.312 və 2.1.313 versiyalarında backdoor tapdığını bildirib. Kod extension yüklənən kimi işə düşür, `~/.ssh/authorized_keys`-ə hücumçunun açarını əlavə edir, SSH-ı açmağa çalışır və xarici serverə reverse SSH tunnel qurur.

**Niyə vacibdir:** Claude Code-u IDE extension kimi işlədənlər üçün birbaşa təhlükədir: extension-ı silmək backdoor-u silmir, persistence (LaunchAgent, cron, scheduled task) qalır.

**Mühəndis üçün nəticə:** Cursor-da bu extension-ın versiyasını yoxla; 2.1.312/2.1.313 qurulubsa, `~/.ssh/authorized_keys`, LaunchAgents/cron və gedən SSH bağlantılarını yoxla, şübhə varsa credential-ları dəyiş. VS Code Marketplace və Anthropic tərəfindən rəsmi təsdiq hələ yoxlanılmayıb.

**Faktlar:**
- Phorion hesabatı 30 oktyabrda dərc olunub, 31 oktyabrda 2.1.312 versiyası əlavə edilib.
- Phorion-a görə zərərli kod `~/.ssh/authorized_keys`-ə açar yazır, reverse SSH tunnel açır və macOS/Linux/Windows-da persistence qurur.
- anthropic.com/news səhifəsində 29–31 oktyabr üçün bu barədə bəyanat yoxdur.

**Şərh:**
- Hücum IDE extension marketplace-lərinin supply chain zəifliyini göstərir.

**Yoxlanılan iddialar:**
- ⚠️ təsdiqlənməyib: Claude Code for VS Code extension 2.1.312 and 2.1.313 on the Cursor Marketplace contained a backdoor; Cursor removed them — Only the Phorion report (security vendor) was read; it cites a Cursor security notice that was not opened. anthropic.com/news has no statement for Oct 29–31.

**Mənbə:** [Phorion](https://phorion.io/blog/offical-claude-code-vsx-compromise/) (Tier 3) · nəşr: 2026-10-30 · aşkar edilib: 2026-10-31
**Əlavə mənbələr:** [Hacker News](https://news.ycombinator.com/item?id=50300683) (Tier 3, commentary)

### 2. follow-redirects: Cross-realm sensitiveHeaders arrays are discarded and custom credentials can follow redirects (CVE-2026-116689; follow-redirects)

*Təhlükəsizlik xəbərdarlığı* · security, frontend · follow-redirects, Node.js, npm

follow-redirects 1.16.0–1.16.1 `sensitiveHeaders` seçimini `instanceof Array` ilə yoxlayır; başqa JavaScript realm-də yaradılmış array səssizcə boş siyahı ilə əvəzlənir və xüsusi credential header-i hücumçunun cross-origin redirect ünvanına gedə bilir. Düzəliş 1.16.2-dədir.

**Niyə vacibdir:** follow-redirects axios kimi geniş istifadə olunan paketlərin dependency-sidir; problem yalnız `sensitiveHeaders` istifadə edənlərə aiddir, amma səssizdir.

**Mühəndis üçün nəticə:** `npm ls follow-redirects` ilə versiyanı yoxla və 1.16.2-yə yüksəlt; `sensitiveHeaders`-i başqa realm-dən (vm, iframe, worker) gələn array ilə ötürürsənsə, xüsusilə vacibdir.

**Faktlar:**
- Təsirlənən versiyalar 1.16.0–1.16.1, düzəliş 1.16.2.
- Ciddilik: High (CVSS 4.0 bal 8.2).

**Yoxlanılan iddialar:**
- ✅ təsdiqlənib: CVE-2026-116689, High (CVSS 4.0: 8.2): follow-redirects >=1.16.0 <=1.16.1 affected, fixed in 1.16.2 — [mənbə](https://github.com/advisories/GHSA-mrwp-f3q8-3g9p)

**Mənbə:** [GitHub Advisory Database](https://github.com/advisories/GHSA-mrwp-f3q8-3g9p) (Tier 1) · nəşr: 2026-10-30 · aşkar edilib: 2026-10-31

### 3. Forge: PKCS#12 MAC forgery and constant-key PBE via zero iteration count (CVE-2026-118782; node-forge)

*Təhlükəsizlik xəbərdarlığı* · security, frontend · node-forge, PKCS#12, Node.js

node-forge `pkcs12FromAsn1()` PKCS#12 MAC iteration count-u 0 (və ya mənfi) qəbul edirdi; bu halda key derivation parol və salt-dan asılı olmayan sabit açar qaytarır. Parolu bilməyən hücumçu PFX faylını dəyişib istənilən parolla təsdiqlənən MAC hesablaya bilər. Düzəliş 1.4.1-dədir.

**Niyə vacibdir:** node-forge sertifikat və açar emalı üçün geniş istifadə olunur; eyni gün paket üçün daha bir neçə High advisory (TLS DoS, PEM ReDoS, X.509 basicConstraints bypass) dərc olunub.

**Mühəndis üçün nəticə:** `npm ls node-forge` ilə yoxla və 1.4.1-ə yüksəlt; istifadəçidən gələn PKCS#12/PFX fayllarını emal edirsənsə, yeniləmə təcilidir.

**Faktlar:**
- Təsirlənən versiyalar ≤ 1.4.0, düzəliş 1.4.1.
- Ciddilik: High (CVSS 7.5).

**Şərh:**
- Eyni pəncərədə node-forge üçün 5 əlavə High advisory toplanıb; onların versiya detalları bu hesabatda ayrıca yoxlanılmayıb.

**Yoxlanılan iddialar:**
- ✅ təsdiqlənib: CVE-2026-118782, High (CVSS 7.5): node-forge <=1.4.0 affected, fixed in 1.4.1 — [mənbə](https://github.com/advisories/GHSA-jc66-7q78-782g)

**Mənbə:** [GitHub Advisory Database](https://github.com/advisories/GHSA-jc66-7q78-782g) (Tier 1) · nəşr: 2026-10-30 · aşkar edilib: 2026-10-31

### 4. Node.js 27.0.0-alpha.0.0.0 (Alpha)

*Rəsmi buraxılış / elan* · frontend, system-design · Node.js, V8, OpenSSL

Node.js 27.x xəttinin ilk alpha-sı çıxıb: V8 15.6 (`Math.sumPrecise()`, `Iterator.zip()`), default heap limiti dəyişib (fiziki yaddaşın yarısı, 256 MB–4 GB, Buffer yaddaşı da sayılır), `v8.serialize()`/`structuredClone()` formatı köhnə versiyalarla uyğun deyil.

**Niyə vacibdir:** Breaking change-lər erkən görünür: OpenSSL 3+ tələb olunur, bundled FIPS provider və OpenSSL engine dəstəyi çıxarılır, `domain` runtime-deprecated olur, Intel macOS experimental-a endirilir.

**Mühəndis üçün nəticə:** Production üçün deyil. Amma `--max-old-space-size`-ə güvənmədən yaddaş limitinə söykənən servislər və proseslər arası serialization istifadə edən kod 27-yə keçiddə yoxlanmalıdır.

**Faktlar:**
- Versiya: 27.0.0-alpha.0.0.0, tarix 2026-10-29.
- V8 15.6.75.13-ə yenilənib.
- Default heap limiti: fiziki yaddaşın yarısı, 256 MB–4 GB aralığında.

**Şərh:**
- Heap limiti dəyişikliyi konteynerlərdə gözlənilməz OOM-a səbəb ola bilər.

**Yoxlanılan iddialar:**

### 5. 4 real? Tracking exploitation and patching of eMudhra’s weak keys

*Ekosistem dəyişikliyi* · security, system-design · TLS, PKI, Certificate Transparency, eMudhra

Cloudflare eMudhra CA-nın zəif intermediate açarlarını necə patch etdiyini yazır: açarlar ictimai sertifikatlardan bərpa oluna bilirdi, yəni Certificate Transparency tələb etməyən patch-lənməmiş client-lər üçün istənilən domen adına sertifikat buraxmaq mümkün idi.

**Niyə vacibdir:** Cloudflare bir həftədə ~22 000 bu açarlarla handshake cəhdi qeydə alıb, ~160-ı başqa təşkilatların domenləri üçün idi; ölçmələrə görə böyük şəbəkələrdə probe-ların yarıdan çoxu hələ də zəif zənciri qəbul edir.

**Mühəndis üçün nəticə:** Öz servislərin və cihazların trust store-unun yeniləndiyini yoxla (xüsusilə köhnə Android WebView, IoT, bot/agent-lər); TLS client yazırsansa Certificate Transparency yoxlaması əlavə müdafiədir.

**Faktlar:**
- Cloudflare 19 oktyabrda xəbər tutub, yüksək prioritetli sistemləri həmin gündən patch-ləyib.
- Pingora loqları bir həftədə ~22 000 zəif açarla handshake cəhdi göstərib.

**Şərh:**
- Ölçmələr bot trafiki ilə təhrif oluna bilər — Cloudflare özü bunu qeyd edir.

**Proqnozlar:**
- eMudhra public CA biznesindən çıxır; trust store-lardan tam çıxarılma gözlənilir.

**Yoxlanılan iddialar:**
- ⚠️ təsdiqlənməyib: eMudhra intermediate private keys were weak and recoverable from public certificates, enabling certificates for any domain on clients without CT enforcement — Cloudflare's analysis (Tier 2); no eMudhra or CA/Browser Forum notice was opened in this run.

**Mənbə:** [The Cloudflare Blog](https://blog.cloudflare.com/emudhra-patching/) (Tier 2) · nəşr: 2026-10-30 · aşkar edilib: 2026-10-31
